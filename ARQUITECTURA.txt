======================
                ELIAOCULAR - ARQUITECTURA DEL SISTEMA
================================================================================

Sistema de diagnóstico y análisis de enfermedades oculares con inteligencia
artificial. Aplica tecnología de aprendizaje profundo (deep learning) para
clasificar imágenes de la retina/fondo de ojo e identificar patologías como
catarata, glaucoma, retinopatía diabética y degeneración macular.

--------------------------------------------------------------------------------
1. VISTA GENERAL (ARQUITECTURA DE ALTO NIVEL)
--------------------------------------------------------------------------------

                      +---------------------------+
                      |        NAVEGADOR          |
                      |  React 18 + Vite + Tailwind|
                      +-------------+-------------+
                                    |  HTTPS / HTTP
                                    v
                     +-------------+-------------+
                     |   FRONTEND  (SPA - Vite)  |
                     |  React Router, Axios,      |
                     |  AuthContext, Recharts     |
                     +-------------+-------------+
                                    |  REST API (JSON) / JWT Bearer

                     +------+----------+---------+
                            |          |
               +------------+          +-----------+
               |                                  |
               v                                  v
     +---------+-----------+            +---------+---------+
     |  MÓDULO AI (IA)     |            |  BASE DE DATOS    |
     |  TensorFlow/Keras   |            |  MySQL 8           |
     |  EfficientNet-B0     |            |  SQLAlchemy ORM    |
     |  Entrenamiento/      |            +-------------------+
     |  Inferencia/Reportes |
     +---------------------+

FLUJO PRINCIPAL:
  1. El usuario se autentica (JWT) desde el frontend.
  2. El frontend envía peticiones REST a FastAPI.
  3. FastAPI valida permisos por rol, procesa la lógica y consulta MySQL.
  4. Para diagnóstico, el backend invoca el módulo AI (TensorFlow) que
     clasifica la imagen.
  5. Los resultados se persisten y se devuelven al frontend.
  6. Opcionalmente se genera un reporte PDF (ReportLab).

2.2 SEGURIDAD Y AUTENTICACIÓN
--------------------------------------------------------------------------------
  - Contraseñas: hash con Bcrypt (Passlib).
  - Sesión: token JWT (HS256), firmado con SECRET_KEY.
  - Expiración: ACCESS_TOKEN_EXPIRE_MINUTES (por defecto 1 día).
  - Flujo: /auth/login -> devuelve access_token; el cliente lo envía como
    header "Authorization: Bearer <token>".
  - OAuth2PasswordBearer + get_current_user validan cada petición protegida.
  - Roles: paciente, medico, administrador.
    * paciente: solo ve/accede a sus propios datos.
    * medico: gestiona pacientes, sube imágenes, diagnostica.
    * administrador: gestiona doctores y todo lo anterior.

3. MÓDULO DE INTELIGENCIA ARTIFICIAL (backend/ai)
--------------------------------------------------------------------------------

  - Modelo: Red neuronal convolucional (CNN) estilo EfficientNet-B0 con
    bloques de convoluciones depthwise-separable, BatchNorm, activación
    "swish" y capa final Dense softmax.
  - Entradas: imágenes RGB 224x224 normalizadas a [0,1].
  - Clases de salida (NUM_CLASSES=5):
      * Catarata
      * Glaucoma
      * Retinopatía diabética
      * Degeneración macular
      * Retina sana

  preprocesamiento.py (OpenCV):
      * remove_noise      -> Filtro Gaussiano
      * enhance_contrast  -> CLAHE (ecualización de contraste adaptativo)
      * resize_image      -> 224x224
      * normalize_image   -> píxeles a [0,1]
      * augment_image     -> rotación, volteo, brillo, zoom (data augmentation)
      * validate_image    -> valida el archivo de imagen

  training.py (TensorFlow):
      * OcularDataset     -> carga imágenes de carpeta por clase
      * OcularTrainer     -> compila el modelo, entrena con EarlyStopping,
                             ModelCheckpoint, ReduceLROnPlateau y class weights;
                             calcula matriz de confusión y reporte de clasificación
                             (scikit-learn); guarda modelo .keras y resultados JSON.
      * Nota: El endpoint /plant/training devuelve un entrenamiento SIMULADO
        (valores sintéticos/aleatorios), no el entrenamiento real del módulo ai.

  inference.py:
      * OcularInference   -> carga el modelo y hace predicción por imagen.
      * inference_service -> instancia global usada por /medical/diagnose.
      * Si el modelo no está cargado o la predicción falla, se usa un
        FALLBACK que genera un diagnóstico aleatorio (plantilla) para no romper
        la API.

5. FLUJOS DE NEGOCIO CLAVE
--------------------------------------------------------------------------------

5.1 DIAGNÓSTICO MÉDICO
  1. El médico sube la imagen (POST /medical/upload) y se guarda en uploads/.
  2. POST /medical/diagnose/{image_id}:
       - Verifica si ya existe diagnóstico (evita duplicados).
       - Intenta usar inference_service (TensorFlow).
       - Si falla, usa fallback aleatorio.
       - Crea registro en diagnoses y en clinical_history.
  3. GET /medical/results o /history/{patient_id} para consultar resultados.
  4. GET /medical/stats para métricas globales.

5.2 ANÁLISIS DE DATASET (MÓDULO PLANT/IA)
  1. El usuario sube un ZIP con carpetas por clase (POST /plant/upload).
  2. El backend valida el ZIP, cuenta imágenes por clase y lo persiste
     como UploadedDataset (preview_data guarda el zip_path).
  3. El resto de endpoints (/overview, /training, /evaluation, /matriz,
     /reporte, /predicciones) devuelven datos SINTÉTICOS generados en tiempo
     real a partir de la distribución de clases del dataset subido.

--------------------------------------------------------------------------------
6. GENERACIÓN DE REPORTES PDF
--------------------------------------------------------------------------------
  - services/pdf_generation.py usa ReportLab (platypus).
  - Genera reporte A4 con: información del paciente, resultados del
    diagnóstico, imagen médica, recomendaciones, información y firma del doctor.
  - Se guarda en backend/reports/ y devuelve la ruta del archivo.
